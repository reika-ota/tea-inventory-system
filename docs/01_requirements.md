## 1. 概要

### 1.1 目的
家庭にあるお茶（茶葉・ティーバッグ）の銘柄ごとの残量と賞味期限を把握し、家族間で共有できるようにする。

### 1.2 背景・現状の課題
- 現在は記憶で管理しており、不定期にテキストで棚卸しを行っている
- どの銘柄がどれだけ残っているか、賞味期限がいつかを即座に把握できない
- 家族間で在庫状況を共有する手段がない

### 1.3 付随する目的
- 要件定義〜テストまでの開発工程を一通り経験する（学習）
- 在庫管理システムの基本的な考え方（マスタ／ロット、差分更新、排他制御、履歴管理）を実装を通じて学ぶ

### 1.4 利用者
| 利用者 | 人数 | 利用端末 |
|---|---|---|
| 本人 | 1 | スマートフォン（主）、PC |
| 家族 | 1〜2 | スマートフォン |

一般公開はしない。

## 2. 用語定義

| 用語 | 定義 |
|---|---|
| 銘柄 | お茶の商品単位（例：白牡丹、ウバハイランズクオリティ）。銘柄マスタで管理する |
| ジャンル | お茶の分類（例：紅茶、ウーロン茶、白茶）。1銘柄につき1つ |
| フレーバー | 香り・ブレンド要素のタグ（例：桜、キンモクセイ、ハイビスカス）。1銘柄に複数付与可 |
| 形態 | 茶葉 または ティーバッグ。残量の単位を決定する（茶葉＝g、ティーバッグ＝個） |
| ロット | 購入単位の在庫。1回の購入につき1ロット。残量・賞味期限を持つ |
| 1回分の量 | 1杯に使用する量。ティーバッグは1個固定 |
| 杯数 | 1回の消費操作でまとめて減算する数（1杯＝1回分の量） |
| 残り回数 | 残量 ÷ 1回分の量（切り捨て） |
| 使い切り | ロットの残量がなくなり、在庫から外すこと（論理削除） |

## 3. 機能要件

### 3.1 マスタ管理
| ID | 機能 | 内容 |
|---|---|---|
| FR-01 | ジャンル管理 | ジャンルの登録・編集・削除・並べ替えができる。ジャンルには色（お茶の水色）を設定し、色は色マスタの候補から選択する |
| FR-02 | 銘柄登録 | 銘柄名、ジャンル、フレーバー（複数）、形態、1回分の量、購入店（任意）、メモ（任意）を登録できる。1回分の量の既定値は茶葉3g、ティーバッグ1個とする |
| FR-03 | 銘柄編集 | 銘柄マスタの内容を編集できる |
| FR-04 | 銘柄削除 | 今後購入しない銘柄を論理削除できる。有効なロット（使い切りでないロット）が残っている銘柄は削除できない。削除済み銘柄は復元できる |

### 3.2 在庫管理
| ID | 機能 | 内容 |
|---|---|---|
| FR-11 | 購入登録 | 銘柄を選択し、購入量・賞味期限（任意）・購入日を入力してロットを作成する |
| FR-12 | 再購入 | 在庫なしの銘柄から、マスタ情報を再入力せずに新規ロットを作成できる |
| FR-13 | 買い足し | 在庫がある銘柄にも、別ロットとして入庫できる |
| FR-14 | 消費 | 銘柄詳細画面で杯数（初期値1）を選択して「飲んだ」操作を行い、1回分の量×杯数を減算する（2人分をまとめて減算する等）。ブレンド時等のため、量を直接指定して減算することもできる |
| FR-15 | 消費ロットの決定 | 複数ロットがある場合、既定では賞味期限が近いロットから減算する（先期限先出し。賞味期限未入力のロットは期限ありのロットの後、購入日が古い順）。ロットを指定して減算することもできる。1回の消費は1ロットに限定し、ロットをまたいだ減算は行わない |
| FR-16 | 残量調整 | 残量を手入力で修正できる（棚卸し・計量誤差の補正） |
| FR-17 | 使い切り | 残量が0以下になった場合、使い切り（ロットの論理削除）を確認するダイアログを表示する。1回分未満の端数が残る場合は「残り全部使った」を選択できる |
| FR-18 | 使い切りの取り消し | 誤操作で使い切りにしたロットを復元できる |

### 3.3 参照・集計
| ID | 機能 | 内容 |
|---|---|---|
| FR-21 | 在庫一覧 | 銘柄単位で、合計残量・残り回数・最も近い賞味期限を表示する。展開するとロットの内訳を表示する |
| FR-22 | 絞り込み・並び替え | ジャンル・フレーバー・形態で絞り込み、残量・賞味期限・銘柄名で並び替えができる |
| FR-23 | ジャンル別集計 | ジャンルごとの銘柄数と合計残量を表示する。単位（g／個）は分けて表示する |
| FR-24 | 強調表示 | 賞味期限が近いもの・切れたもの、残り回数が少ないものを一覧上で強調表示する（賞味期限未入力のロットは期限による強調の対象外） |
| FR-25 | 在庫なし一覧 | 有効なロットを持たない銘柄を別枠で表示し、再購入（FR-12）の起点とする |
| FR-26 | 履歴参照 | 銘柄・ロットごとの在庫増減履歴を参照できる |

## 4. 非機能要件

| ID | 分類 | 内容 |
|---|---|---|
| NFR-01 | コスト | 無料のサービスのみで構築・運用する |
| NFR-02 | アクセス制御 | 家族のみがアクセスでき、第三者はデータを閲覧・更新できない |
| NFR-03 | 利便性（認証） | 毎回の起動時に認証操作を必要としない（初回のみ等） |
| NFR-04 | 利用端末 | スマートフォンのブラウザで快適に操作できる（レスポンシブ対応） |
| NFR-05 | データ共有 | 複数端末から同一データを参照・更新できる |
| NFR-06 | 整合性（同時更新） | 同時更新が発生してもデータ不整合が起きない。在庫増減は差分で送信しサーバー側で計算する。サーバー側で排他制御を行う |
| NFR-07 | 整合性（上書き） | マスタ編集・残量調整など上書き系の操作は楽観ロックで競合を検知する |
| NFR-08 | 冪等性 | 同一操作が重複送信（連打・リトライ）されても結果が変わらない |
| NFR-09 | 追跡性 | すべての在庫増減を、日時・操作者・対象ロット・増減量・理由区分とともに履歴として記録する |
| NFR-10 | データ保全 | 削除は論理削除とし、履歴との参照関係を維持する |

## 5. データ要件（概念レベル）

| データ | 主な項目 |
|---|---|
| ジャンルマスタ | ジャンル名、色、表示順 |
| 色マスタ | 色コード、色名、表示順（ジャンルの色の候補） |
| 銘柄マスタ | 銘柄名、ジャンル、フレーバー、形態、1回分の量、購入店、メモ、削除フラグ、版 |
| 在庫ロット | 銘柄、購入量、残量、賞味期限（任意）、購入日、使い切りフラグ、版 |
| 在庫履歴 | 操作ID、日時、操作者、ロット、増減量、理由区分（購入／消費／残量修正／使い切り／使い切り取り消し） |

## 6. 対象外（今回のスコープに含めない）

- アプリ外への通知（メール・LINE・プッシュ通知等）
- 一般公開・不特定多数での利用
- 購入価格・支出の管理
- バーコード読み取り
- 消費量の統計・グラフ（履歴データは保持するため、将来拡張は可能）
- 色マスタを編集する画面（色の追加はスプレッドシートを直接編集して行う）

## 7. 制約事項

- 無料のサービス（GitHub Pages、Google スプレッドシート、Google Apps Script 等）を前提とする
- データストアにトランザクション機能がない可能性を考慮し、アプリ側で整合性を担保する
